Правило границ

Движок не знает про игрока, интерфейс ничего не решает, а логика клиента ни на что не влияет — истина у сервера, а общие правила лежат в primitive_shared.

Это одно предложение объясняет, почему файлы лежат именно так. Границы слоёв описаны не в общей документации, а в mod.rs каждого каталога: что в него входит, чего в нём быть не должно, и почему. Комментарий рядом с границей переживает переезд файла; отдельный документ про архитектуру — нет.

Плюс сами моды — mods/greeter, mods/flight, mods/sandbox, mods/dypt — они лежат внутри рабочего пространства, а не рядом с ним. Причина в этом и есть: изменение мод-API, ломающее мод, ломает сборку, а не чьи-то планы на выходные. Подробнее — на странице для разработчиков модов.

primitive_shared — правила

Всё, о чём клиент и сервер обязаны думать одинаково. Если правило живёт здесь, разойтись двум сторонам негде.

primitive_shared/src/
├── blocks.rs      # ТАБЛИЦА БЛОКОВ: строка на блок, все его свойства подряд
├── types.rs       # идентификаторы, размеры чанка, поля ячейки, запросы к таблице
├── worldgen.rs    # рельеф, биомы, климат, пещеры, деревья, жилы, реки
├── lighting.rs    # инкрементальный свет в мировых координатах
├── protocol.rs    # рукопожатие, батчи, тик-снапшоты, версия протокола
├── inventory.rs   # слоты и стопки
├── crafting.rs    # таблица рецептов: меню и сервер читают одну и ту же
├── geometry.rs    # коллайдер игрока, коробки блоков, шаг
├── combat.rs      # что стоит удар и куда он дотягивается
├── fluid.rs       # вода как уровень: сколько в ячейке и куда оно пойдёт
├── load.rs        # чем обходится тяжёлый рюкзак
└── net.rs         # bincode с префиксом длины

Таблица блоков — это данные, а не код. Строка на блок, все свойства подряд, имена совпадают с именами в assets/textures/blocks.toml и в сохранениях. Поэтому имена блоков и рецептов остались английскими даже в русском интерфейсе: перевести их значит перевести формат файла.

primitive_server — решения

primitive_server/src/
├── lib.rs           # процесс: приём соединений, тик-луп, метрики, автосохранение
├── main.rs          # тонкий бинарник поверх lib.rs
├── settings.rs      # ~30 параметров + секция [anticheat]
├── net/             # СЕТЬ
│   ├── connection.rs   # рукопожатие, чтение, запись, подкачка чанков
│   └── players.rs      # реестр, очереди, индекс подписок на чанки
└── logic/           # ЛОГИКА: всё, о чём сервер решает сам
    ├── world.rs        # 32 шарда, LRU-кэш, оверлей правок, сохранение
    ├── survival.rs     # здоровье, падения, утопление, респавн
    ├── items.rs        # выпавшие стопки и их подбор
    ├── containers.rs   # содержимое сундуков и рюкзаков смерти
    ├── falling.rs      # падающие блоки как сущности
    ├── water.rs        # течение: вниз, потом вбок, и высыхание без источника
    ├── simulation.rs   # форма любой механики, следящей за ячейками
    ├── anticheat.rs    # скорость, полёт, телепорт, дальность, рейт-лимиты
    ├── commands.rs     # команды консоли и чата с уровнями прав
    ├── profiles.rs     # что у игрока было, когда он вышел
    └── plugins.rs      # хост плагинов на Rhai, за cargo-фичей `plugins`

Деление на net/ и logic/ не косметическое: в net/ нет ни одного решения о мире, в logic/ — ни одного чтения из сокета. Мир нарезан на 32 шарда с LRU-кэшем и оверлеем правок сверху, поэтому два игрока в разных концах карты не ждут друг друга.

primitive_client — рабочая копия

primitive_client/src/
├── main.rs          # цикл: ввод -> физика -> сеть -> меш -> рендер
├── audio/           # ЗВУК: всё, что говорит с колонкой
│   ├── synth.rs        # осцилляторы, фильтры, огибающие — примитивы DSP
│   ├── bank.rs         # рецепт на каждый звук + материал каждого блока
│   ├── music.rs        # композитор: пишет музыку, пока играет
│   ├── mixer.rs        # голоса, панорама, мастер-шина
│   └── soundscape.rs   # шаги, погода, выбор настроения
├── engine/          # ДВИЖОК: всё, что говорит с GPU
│   ├── renderer.rs     # проходы: сплошной, вырез, смешивание, актёры, UI
│   ├── arena.rs        # весь террейн в двух буферах: одна привязка на кадр
│   ├── item_model.rs   # 3D-модель предмета из его спрайта
│   ├── mesh.rs         # отсечение граней, AO, упакованная вершина, тинт листвы
│   ├── mesher.rs       # построение мешей и света в фоновых потоках
│   ├── texture.rs      # массив текстур блоков и глифов
│   └── *.wgsl          # шейдеры: террейн, актёры, небо, интерфейс, рука
├── net/             # сокет, фоновые чтение и запись, интерполяция игроков
├── ui/              # ИНТЕРФЕЙС: меню, HUD, чат, инвентарь, четыре языка
└── logic/           # ЛОГИКА клиента — рабочая копия, не истина

Слово «рабочая копия» здесь техническое. Клиент считает физику у себя, иначе каждый шаг стоил бы круга по сети; но всё, что он посчитал, сервер вправе отменить. Поэтому в logic/ клиента нет ни одного места, которое что-то окончательно решает — там только предсказание и его коррекция.

Кто источник истины

Одиночная игра не имеет отдельного пути в коде. Кнопка Play поднимает настоящий сервер внутри процесса клиента, на 127.0.0.1 и на порту, который выдаёт система.

Альтернатива — офлайн-режим в клиенте — это второй генератор мира, вторая физика и вторая симуляция песка, и они расходятся. Здесь реализация мира ровно одна, а одиночная игра отличается от сетевой только тем, чей это процесс.

Локальный мирПочему
порт 0 на loopbackмир недоступен из сети, две копии игры работают рядом
без плагиновне «отключены», а не собраны: движка скриптов в бинарнике игры нет вовсе
без античитаодин процесс не может уличить сам себя во лжи
моды загружаютсяс 1.5: единственный игрок своего мира — оператор

Освещение

Свет живёт в мировых координатах и сохраняется между построениями мешей: считается один раз при загрузке чанка, дальше обновляется инкрементально. Один байт на ячейку — небесный свет в младшем полубайте, блочный в старшем.

Прошлую версию пришлось переписать, и это записано в README как журнал, а не как итог: старый вариант освещал по одному чанку в объём «чанк плюс рамка в один блок», пересобирая его при каждом ремеше — одновременно неверно и медленно. Две ошибки в новой версии нашёл property-тест, третью — расхождение между тем, как считали колонка и заливка.

Мешинг и потоки

Построение мешей уехало в фоновые потоки, и это видно по числам в F3: время кадра, число вызовов отрисовки, сколько чанков отсечено, сколько мешей построено за секунду.

  • Весь террейн в двух буферах — одна привязка на кадр вместо привязки на чанк
  • Мешер шагает, а не считает индекс — соседняя ячейка находится прибавлением, а не умножением
  • Покадровая геометрия в постоянных буферах — то, что меняется каждый кадр, не выделяется каждый кадр
  • Интерес по сетке вместо перебора — сервер не спрашивает у каждого игрока про каждую сущность

Что проверено

Всё, что можно запустить руками, чтобы убедиться, что дерево живое:

cargo test --workspace
cargo run -p primitive_server --example verify_broadcast    # сервер должен быть запущен
cargo run -p primitive_client --example gen_placeholder_textures
cargo build -p flight  && cargo test -p primitive_server --test flight
cargo build -p sandbox && cargo test -p primitive_server --test sandbox
cargo run -p primitive_server --example verify_flight

Два последних — не формальность. Мод собирается настоящим компилятором и грузится через настоящий C ABI, а verify_flight проходит ещё и через настоящий сокет: граница, проверенная только с одной стороны, — это граница, про которую ничего не известно.
