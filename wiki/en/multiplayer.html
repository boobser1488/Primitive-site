Multiplayer

Singleplayer is the same server running inside the game, so a shared world plays exactly like your own.

Joining a server

  1. MULTIPLAYER → ADD (or A).
  2. Give it any NAME and an ADDRESS as host:port. If you leave out the port, :7878 is added. The third field, SERVER PASSWORD, is only for servers that ask for one.
  3. SAVE, pick the server, PLAY.

E edits a server, Del removes it.

  • The connection is always encrypted, to a shared server and to your own world alike.
  • Server key. The first time, the game remembers the server's key. If the same address later answers with a different key, the game refuses and shows SERVER KEY CHANGED with both fingerprints. Trust the new one only if the owner told you they changed it.
  • Server password. A closed server asks for its password when you connect; you can log in once or log in and remember it.
  • Login window. If the server runs the login plugin, a window in a blue frame, marked as the server's own window, asks you to make up a password for your name the first time, and for that password after. The blue frame means the server is writing, not the game. After one login the server gives this device a key, so you only need the password again on a new device. /forgetdevices makes all your devices ask again; /password changes it.

What is different with other people

  • The map is personal: what others have seen, they tell you themselves.
  • Other players are seen as they are dressed, with what they hold.
  • A downed player can be picked up by a friend: right-click them with a bandage, splint, food or a jug, whatever their countdown asks for. It uses your item.
  • A dead player's body can be opened by anyone. On a small server the first to arrive is usually the friend who was there.
  • Footprints next update are seen by everyone: whoever comes later sees your trail already aged.
  • The F3 panel shows coordinates only to operators. Nobody is told where they are; you find your way by landmarks and your own map.

Running your own server

Start primitive_server.exe from the release archive. On first start it writes server_settings.toml beside itself with every value; edit it and restart. The ones usually changed:

SettingMeaning
bind_addraddress and port, 0.0.0.0:7878 by default
server_namethe name players see
world_seedthe world's seed
max_playersplayer limit
view_distance_chunkshow far the server sends the world
world_dirwhere the world is saved (empty: not saved)
server_passworda password for the server; on start it is replaced by a hash
[anticheat]the anticheat section, including enabled

For players outside your network, open the port in the firewall and forward it on the router. The server's key lives in the world folder as server.key; move it with the world, or every player will be told the server was swapped.

The login plugin (plugins/auth) is off by default; set enabled = true in its plugin.toml and restart. Without it and without a password, the log warns that players' identities are not checked: whoever types a name plays as it.

Commands

Typed in the server console, or in chat with a / in front. help lists them all.

CommandWhat it does
listwho is online
playerseveryone the server remembers
say <text>message to everyone
time <0.0-1.0>, day, night, dawn, dusktime of day
weather clear|rain|storm|autoset or release the weather (operator)
tp <x> <y> <z>teleport (operator)
give <block> [n]items into your pack (operator), e.g. give cobblestone 40
kick <name>, op <name>, deop <name>kick, grant and remove operator rights
save, stopsave the world, stop the server

The server remembers each player by an ID made from the name, with their pack, health and where they logged out; a returning player appears where they left. In singleplayer you are the operator only if COMMANDS AND TESTING is on for that world.
