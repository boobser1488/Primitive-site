РАЗРАБОТКА МОДОВ

Три способа расширить игру. Rust-мод собирается против исходников самой игры и получает её настоящие структуры. Нативный мод говорит с сервером через C ABI. Плагин — скрипт на Rhai, который кладут файлом.

Rust-моды — в исходниках, но не в выпуске 1.5.2: они появились после него и войдут в следующую версию. Плагины на Rhai и моды через C ABI есть и в 1.5.2. Старые способы не убраны и не объявлены устаревшими: для простого мода C ABI по-прежнему правильный ответ.

Если сомневаетесь — начните с плагина. Мод через C ABI нужен для генератора, ИИ зверя, работы на каждый блок или тик. Rust-мод — когда нужно поменять саму игру: физику тела, вердикт античита, рельеф, кадр.

Rust-моды

Владелец решил: моды должны работать как в Minecraft — мод получает доступ ко всему коду игры, как Fabric или Forge с Mixin. Поэтому Rust-мод — это крейт cdylib, который зависит от primitive_shared, primitive_server и primitive_client как от обычных библиотек.

Цена принята сознательно: мод привязан к версии игры и к компилятору, работает только на ПК и может уронить игру — его код выполняется в процессе игры без песочницы.

Игра передаёт моду &mut на свои настоящие объекты — &mut Player, &Arc<Context>, &mut AntiCheat, — и мод читает любое поле, меняет любое публичное, вызывает любую публичную функцию. Для этого модули клиента стали публичными; закрыты только frame и audio.

Цепочки вместо Mixin

Mixin в Java переписывает байткод при загрузке. В Rust байткода нет, а патчить машинный код — значит ломаться от каждой пересборки. Поэтому ключевые функции игры вызываются через цепочку, объявленную макросом primitive_shared::hook!. Так объявлена цена приземления (primitive_server/src/rustmod.rs):

primitive_shared::hook! {
    pub mod fall_damage: fn(distance: f32, water_depth: u32, kilograms: f32) -> f32;
}

Место вызова само называет функцию игры (logic/survival.rs). Пока модов нет, это прямой вызов за одной проверкой:

fn fall_through_mods(&self, distance: f32, water_depth: u32) -> f32 {
    match &self.fall_chain {
        None => fall_damage(distance, water_depth, self.carried_kg),
        Some(chain) => chain.call(fall_damage, distance, water_depth, self.carried_kg),
    }
}

Мод вешает обёртку. Обёртка, которая зовёт next, — это @Inject (до, после, вокруг); не зовущая — @Overwrite. Два мода на одну функцию оба работают: каждый получает свой next. Так low_gravity берёт цену приземления у игры — для падения вчетверо короче:

fn landing(distance: f32, water_depth: u32, kilograms: f32, next: &fall_damage::Next) -> f32 {
    next.call(distance * SHARE, water_depth, kilograms)
}

А на клиенте — делает шаг игры и возвращает три четверти гравитации, которую шаг применил. Обёртка, а не копия шага: в шаге тысяча строк коллайдера, воды и ступенек.

#[allow(clippy::too_many_arguments)]
fn step(
    player: &mut Player,
    chunks: &ChunkManager,
    others: &[DVec3],
    wish_dir: Vec3,
    look: Vec3,
    jump_pressed: bool,
    jump_held: bool,
    sprinting: bool,
    dt: f32,
    next: &player_step::Next,
) {
    next.call(player, chunks, others, wish_dir, look, jump_pressed, jump_held, sprinting, dt);
    if !player.grounded && !player.in_water && !player.flying {
        player.velocity.y -= GRAVITY * (1.0 - SHARE) * dt;
    }
}

Цепочки строятся на каждый сервер и каждый клиент и лежат на Context, на Player и на сокете, а не в статиках: в одном процессе бывает несколько серверов, и мод низкой гравитации в одном мире не должен опускать гравитацию в соседнем.

Правило статиков. Мод линкует крейты игры как обычные библиотеки, поэтому у него свои, пустые копии всех статиков игры. Состояние процесса мод получает только в аргументах обёрток и реестров. Рантайм tokio из мода не трогать: мод увидит пустую копию.

Реестры

Чем мод добавляет новое, а не подменяет старое:

РеестрГдеЧто
Content::blockпроцессновый блок: строка BlockDef, картинка 16×16, модель из коробок
ServerRegistrar::on_tickсерверкаждый тик, с &Arc<Context>
ServerRegistrar::on_messageсерверсвой сетевой канал от клиента; ответ — rustmod::send_to
ClientRegistrar::on_frameклиенткаждый кадр: игрок, камера, сокет
ClientRegistrar::on_messageклиентсвой канал от сервера; отправка — rustmod::send
ClientRegistrar::render_passклиентполноэкранный проход в своём WGSL поверх кадра

Блоки модов получают виды 1008–1023, выше последнего вида игры. Античит их принимает, сохранение пишет, /give находит по имени, атлас берёт картинку, мешер — модель. Виды раздаются по порядку загрузки (папки по имени), поэтому удалённый мод оставляет в мире неизвестные клетки — это записано как недоделка.

Проход рендера — одна функция WGSL. Игра оборачивает её вершинным шейдером, кадром как текстурой и атласом блоков и пропускает весь текст через AtlasSplit::specialise, так что проход, читающий атлас, рисует правильный блок и на телефоне с 256 слоями на массив. Проход мода sepia целиком:

fn mod_pass(colour: vec4<f32>, uv: vec2<f32>) -> vec4<f32> {
    let c = colour.rgb;
    let toned = vec3<f32>(
        dot(c, vec3<f32>(0.393, 0.769, 0.189)),
        dot(c, vec3<f32>(0.349, 0.686, 0.168)),
        dot(c, vec3<f32>(0.272, 0.534, 0.131)),
    );
    let corner = distance(uv, vec2<f32>(0.5, 0.5));
    let vignette = 1.0 - smoothstep(0.45, 0.85, corner) * 0.35;
    return vec4<f32>(min(toned, vec3<f32>(1.0)) * vignette, 1.0);
}
pub fn client(registrar: &mut ClientRegistrar) {
    registrar.render_pass("sepia", WGSL);
}

Стороны и проверка при входе

Как в Fabric, мод объявляет сторону:

СторонаГде работаетСпрашивается при входе
Serverтолько сервернет — клиент без него входит
Clientтолько клиентнет — игрок с ним входит на любой сервер
Bothоба концада: тот же набор, те же версии

Клиент называет свои Both-моды в сообщении входа (протокол 76), сервер сравнивает их со своими до проверки пароля и отказывает с причиной, называющей каждый мод и обе версии:

моды на сервере и у вас не совпадают: this server needs the mod
low_gravity 1.0.0, and you do not have it

Совместимость решает отпечаток, а не номер версии. Мод экспортирует C-структуру фиксированного вида со штампом: версия игры, версия компилятора, сторона и отпечатки трёх крейтов игры — хеш компилятора, цели, features и каждого байта src/. Поле, добавленное в ветке, сдвигает раскладку и не меняет версию, поэтому версии мало. Загрузчик сравнивает штамп до первого вызова Rust-кода; при расхождении мод не загружается, а в журнале строка, что не совпало.

Как собрать Rust-мод

Мод живёт в рабочем пространстве игры, как mods/low_gravity, — только так у мода и игры один Cargo.lock. Внешний мод — это клон игры с вашим крейтом в mods/. Из mods/low_gravity/Cargo.toml:

[lib]
name = "low_gravity"
crate-type = ["cdylib"]
path = "src/lib.rs"

[features]
dedicated = ["primitive_server/plugins"]

[dependencies]
primitive_client = { path = "../../primitive_client" }
primitive_server = { path = "../../primitive_server", default-features = false, features = ["mods"] }
primitive_shared = { path = "../../primitive_shared" }

src/lib.rs только ставит штамп; код мода — в src/hooks.rs:

pub mod hooks;

primitive::rust_mod! {
    side: Both,
    server: hooks::server,
    client: hooks::client,
}
pub fn client(registrar: &mut ClientRegistrar) {
    registrar.player_step(step);
}

pub fn server(registrar: &mut ServerRegistrar) {
    registrar.judge_move(judge);
    registrar.fall_damage(landing);
}

Рядом с библиотекой — rustmod.ron. Он говорит загрузчику «здесь Rust-мод»; загрузчик C-модов такую папку пропускает. Версия и сторона вшиты в саму библиотеку.

(
    name: "low_gravity",
    enabled: true,
)

Сборка — вместе с игрой. Мод для отдельного сервера — вторая сборка того же крейта с фичей dedicated: primitive_server.exe собран с плагинами, сервер внутри клиента — без них, и Context у них разный.

cargo build --release -p primitive_client -p low_gravity
copy target\release\low_gravity.dll mods\low_gravity\

cargo build --release -p primitive_server
cargo build --release -p low_gravity --features dedicated
copy target\release\low_gravity.dll <папка сервера>\mods\low_gravity\

Собирать их отдельными вызовами cargo: в одном вызове фичи объединяются. Загруженный мод пишет в журнал:

[rust mods] loaded Rust mod 'low_gravity 1.0.0' (Both)
[rust mods] 'marble_block' added blocks [1008]
[rust mods] 'sepia' draws its pass 'sepia' over the frame

Все четыре — в рабочем пространстве: мод, который трогает структуры игры по имени, должен ломать сборку, а не игру игрока. Сценарии клиента компилируют те же hooks.rs и играют их с настоящим сервером и античитом.

Цена

Без модов игра ведёт себя как раньше: пустая цепочка — это прямой вызов функции игры за проверкой пустого вектора, и компилятор её инлайнит. Замер из docs/modding.md, 50 млн вызовов: напрямую 3,30 нс, через пустую цепочку 3,23, через цепочку с одной обёрткой 3,51. Кадр без модов до и после — 6,987 и 6,988 мс GPU.

Чего пока нет: рецептов и предметов модов, своих экранов и звука, прохода внутри мира до интерфейса, сохранения нумерации блоков модов, модов на Android. Горячей перезагрузки и песочницы не будет: мод не выгружается никогда.

Нативные моды через C ABI

Есть и в 1.5.2. Мод — библиотека, которую загружает сервер (выделенный или встроенный в одиночную игру). Она экспортирует один символ, primitive_mod_register; его пишет макрос primitive_modapi::declare_mod!. Контракт — один файл, primitive_modapi/src/lib.rs, версия API 2.2: таблицы функций хоста и события, всё простыми данными.

mods/
  greeter/
    mod.ron              # манифест: имя, версия, версия API, настройки
    greeter.dll          # windows
    libgreeter.so        # linux
    libgreeter.dylib     # macos
primitive_modapi::declare_mod! {
    name: "greeter",
    version: "1.0.0",
    load: load,
    event: event,
}

Манифест — RON: мод объявляет в settings значения, типов которых хост не знает. Версия API записана и в манифесте, чтобы сервер отказал несовместимому моду, не загружая его код.

Всё через границу — простыми данными

Ни String, ни Vec: у них нет стабильной раскладки. Текст — Str, одолженный на время одного вызова.

Операции, а не структуры

Нет вызова, отдающего устройство чанка: операция переживает переписывание внутренностей, структура его замораживает.

Структуры-выходы заморожены

Новые колонки приезжают новыми структурами, иначе хост пишет за конец буфера старого мода.

Подписка — в on_load

В точке входа других модов ещё нет. Таблицы render, audio и ui на сервере пустые — проверяйте.

Плагины на Rhai

Есть и в 1.5.2. Плагин — папка в plugins/ с plugin.toml и main.rhai. Работает только на выделенном сервере: клиент собран без движка скриптов, и в одиночной игре плагинов нет. Порядок загрузки алфавитный, правки подхватываются при перезапуске сервера.

name = "мой_плагин"          # обязательное
version = "1.0"              # необязательное
author = "кто-то"            # необязательное
description = "что делает"   # необязательное
script = "main.rhai"        # необязательное, это значение по умолчанию
enabled = true               # необязательное, по умолчанию true
fn on_join(player, username) {
    broadcast(username + " зашёл на сервер");
    tell(player, "Привет!");
}
ХукКогдаreturn false
on_load()старт сервера—
on_join(player, username)игрок подключился—
on_leave(player, username)игрок отключился—
on_chat(player, text)сообщение в чатотменить

Скрипту доступны сообщения (broadcast, tell, log), блоки (set_block, get_block, fill), игроки (teleport, kick, player_names), время и постоянное хранилище store. Ни файлов, ни сети, ни процессов: плагин не дотянется до того, чего сервер ему не дал. Мир он видит снимком, зациклившийся скрипт обрывает лимит операций, плагин, упавший десять раз подряд, отключается.

В комплекте: welcome, bedrock_guard, daylight. В следующей версии к ним добавится auth — вход по паролю через окна до мира.
