Если вы не уверены, чего хотите, — вам нужен плагин. Мод нужен для того, чем плагин быть не может: генератор мира, ИИ зверя, механика, считающая на каждый блок или на каждый тик.

Почему скрипты вообще существуют, хотя есть нативная граница: для сервера, куда люди просто кладут файлы, скрипт — правильный размен. Медленнее на вызов, зато сломанный плагин — это строчка в логе, а не падение, а зациклившийся останавливается лимитом операций, а не вешает тик-луп.

Плагин: с чего начать

Плагин — это папка с двумя файлами:

plugins/
  мой_плагин/
    plugin.toml     # метаданные
    main.rhai       # скрипт
name = "мой_плагин"          # обязательное
version = "1.0"              # необязательное
author = "кто-то"            # необязательное
description = "что делает"   # необязательное
script = "main.rhai"         # необязательное, это значение по умолчанию
enabled = true               # необязательное, по умолчанию true

Скрипт определяет любое подмножество хуков; ненужные просто не пишутся — отсутствующий хук не ошибка:

fn on_join(player, username) {
    broadcast(username + " зашёл на сервер");
    tell(player, "Привет!");
}

Сервер сканирует каталог при запуске, путь настраивается через plugin_dir в settings.toml. Порядок загрузки алфавитный — чтобы он не зависел от прихоти файловой системы: от него зависит, какой плагин увидит событие первым. На лету плагины не перезагружаются, правки подхватываются при перезапуске сервера.

Хуки блоков отменяющие, а не уведомляющие. Плагину защиты нужно успеть сказать «нет» до изменения мира, а не откатывать уже случившееся. Вето одного плагина достаточно — поэтому несколько защитных плагинов складываются между собой без договорённостей.

on_tick вызывается раз в секунду, а не каждый такт: скрипт, который запускается двадцать раз в секунду, — это ловушка для автора плагина, и ничему здесь не нужна точность такта.

Ни файлов, ни сети, ни процессов не зарегистрировано: плагин не дотянется до того, чего сервер ему не дал. Это не песочница поверх языка, а просто отсутствие таких функций в его словаре.

Границы плагина

  • Мир скрипт видит как снимок, собранный заранее. Хук вызывается, когда сервер уже может держать блокировки мира и реестра, поэтому обращение скрипта обратно в живое состояние привело бы к взаимоблокировке тик-лупа. По той же причине действия скрипта возвращаются как данные и применяются после его завершения.
  • get_block отдаёт только ячейки, относящиеся к событию; на остальные вернёт −1.
  • Встроенные команды приоритетнее. /players — синоним /list, поэтому до плагина он не дойдёт, и подменить /stop нельзя.
  • Плагин, который валится десять раз подряд, отключается.

В комплекте три примера: welcome (приветствия и своя команда /online), bedrock_guard (защита дна мира и радиуса вокруг спавна) и daylight (объявление заката; выключен по умолчанию — пример состояния между вызовами). Полное руководство — plugins/README.md.

Нативный мод

Мод — это библиотека, которую сервер грузит при запуске. Она экспортирует ровно один символ, primitive_mod_register, и макрос primitive_modapi::declare_mod! пишет его за вас.

mods/
  greeter/
    mod.ron              # манифест: имя, версия, версия API, настройки
    greeter.dll          # windows
    libgreeter.so        # linux
    libgreeter.dylib     # macos
primitive_modapi::declare_mod! {
    name: "greeter",
    version: "1.0.0",
    load: load,
    event: event,
}

Манифест — RON, а не TOML, и это не вкусовщина: мод объявляет в settings значения, типов которых хост не знает, а RON — нотация с типами внутри. Версия API объявлена и в манифесте тоже, чтобы сервер мог отказать несовместимому моду не загружая его код: открытие библиотеки запускает её инициализаторы, и мод, собранный против другой мажорной версии контракта, — ровно тот, которому не стоит дать что-либо выполнить до проверки.

Сборка и установка:

cargo build -p flight --release
copy target\release\flight.dll mods\flight\      # Windows
cp    target/release/libflight.so mods/flight/   # Linux

Дальше запустить сервер и посмотреть в лог:

[mods] loaded mod 'greeter' 1.0.0 (API 2.0)
[mods] 1 active

Команда /mods перечисляет загруженное — плагины и моды вместе.

Правила границы

Контракт — один файл, primitive_modapi/src/lib.rs: 181 функция хоста в двадцати таблицах и 35 событий, всё через C ABI, всё простыми данными. Мод собирается против него и больше ни против чего — иначе «стабильный API» был бы обещанием про сто тысяч строк игрового кода вместо обещания про один файл.

Всё переходит границу простыми данными

Ни String, ни Vec, ни Result — у них нет стабильной раскладки между версиями компилятора. Текст — это Str (указатель и длина), и он одолжен на время одного вызова. Что хотите сохранить — копируйте.

Проверяйте версию в обе стороны

Хост проверяет вашу и откажет при расхождении. Проверяйте и его: мод, загруженный более старым хостом, иначе прочитает за концом таблицы раньше, чем успеет пожаловаться.

Структуры-выходы заморожены

Мод кладёт BlockProperties или PlayerVitals к себе на стек и отдаёт хосту указатель. Дорастить такую структуру значит заставить хост писать за конец чужого буфера — порча стека, которую проверка версии не поймает, потому что проверка прошла. Новые колонки приезжают новыми структурами.

Операции, а не структуры

Нет вызова, отдающего устройство чанка или очередь симуляции воды, и не будет: операция переживает переписывание внутренностей, структура его замораживает. Симуляцию воды здесь уже переписывали дважды.

Пустая таблица — «не в этом процессе»

render, audio и ui равны null на выделенном сервере. Проверяйте их.

Подписывайтесь в on_load

Не в точке входа: там других модов ещё не существует.

Таблицы контракта: Core, World, Generation, Blocks, Items, Entities, Players, Inventory, Network, Events, Physics, Save, Crafting, Lighting, Food, Combat, Fluid, Containers, Stations, Simulation — плюс Render, Audio и Ui, которых на сервере нет.

Моды в комплекте

greeterРабочий пример. Всё, что автор мода делает хотя бы раз, сделано там по разу и с объяснением рядом: подписка, чтение настройки из манифеста, состояние, переживающее рестарт, отмена действия, ответ на команду.
flight/fly. Первое, что пользуется возможностью, которую API отрастил ради него — PlayersApi::set_flying.
sandbox/sandbox. Диагностика: зовёт каждую функцию каждой таблицы и считает каждое событие.
dypt/dypt. Язык программирования внутри мира — точка расширения поверх точки расширения: моды на dypt пишутся без сборки и перечитываются по /dypt reload.

sandbox поставляется выключенным, и это не осторожность, а следствие его устройства: он подписан на все события — иначе он не скажет, какие не приходят, — а мод, подписанный на всё, это диспатч на каждый тик, на каждую ячейку, которую сдвинула вода, и на каждую вещь, которую кто-то поднял. Включили, спросили /sandbox, выключили.

/sandbox events печатает, сколько событий каждого рода пришло, нулями вперёд — потому что ноль здесь и есть новость.

Где проходит граница: полёт

flight заодно показывает, чего модом сделать нельзя. Чистым модом полёт на этом сервере не сделать: клиент считает гравитацию у себя, и ничто со стороны сервера не мешает игроку падать. Очевидный обход — телепортировать его вверх каждый тик — ломается тремя способами сразу: телепорт обнуляет скорость, ускорение в воздухе ограничено, а каждая коррекция пишет игроку на экран «отброшен назад» двадцать раз в секунду.

Поэтому движок отрастил возможность, а мод владеет политикой: сервер умеет разрешить игроку не падать, а кому и когда это разрешено — решает мод. По умолчанию /fly доступен только операторам (operators_only в flight/mod.ron). Это безопасное значение, а не дружелюбное: мод, раздающий полёт всем на публичном сервере, изменил игру для всех, кто его не ставил.

Посмотреть загруженное/mods

Одиночная игра тоже грузит моды — с версии 1.5. До этого не грузила, и довод был такой: «в локальном мире нет оператора, для которого ставят моды». Довод оказался неверен насчёт того, кто ставит мод: это сам играющий, на своей машине, в папку, которую он видит. Поэтому клиент запрашивает фичу mods по имени — и только её, движка скриптов он по-прежнему не линкует, — папка ищется рядом с исполняемым файлом, а единственный игрок локального мира считается оператором.

Android — намеренное исключение: мод это .so, который игрок кладёт в папку, а в APK такой папки, доступной обычному человеку, нет.
